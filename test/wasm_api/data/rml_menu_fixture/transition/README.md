# RmlUi menu transition fixture

This fixture runs the real interactive engine through two complete
menu-to-game-to-menu cycles. It uses the same `WasmMenu/` directory as the
basic fixture and adds a tiny bare game plus a LuaMenu driver. The map is
generated by the engine from `startscript.txt` parameters; there is no map
archive in this fixture.

The game package contains only `modinfo.lua`, `gamedata/modrules.lua`, and a
LuaUI `Update` hook. The menu driver loads the checked-in `startscript.txt`
from its menu archive and calls `Spring.Reload(startScript)` after
the RmlUi menu has been activated. The game returns with `Spring.Reload("")`
after 30 updates. The third menu activation quits after the menu has had time
to initialize again.

From the repository root, after building with
`./docker-build-v2/build.sh linux -DUSE_ASAN=ON`, run:

```sh
python3 test/wasm_api/data/rml_menu_fixture/transition/run.py
```

Use `--native` to build the Rust fixture and run the same cycle through the
native menu transport. The script leaves its isolated directory in `/tmp` so
the log can be inspected after the process exits.

The retained log must contain three menu activations, two generated game
starts, two returns to menu, and the final completion message. It should also
contain `MapGen::` output for `rmlui_transition_generated_10x8`; this confirms
that map generation came from the start script rather than a map archive. The
engine is allowed to report existing LeakSanitizer allocations after its
natural shutdown; those are reported by the command's exit status and must be
compared with a baseline run separately.
