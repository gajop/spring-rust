# Columns: one property of many units a call · 2026-10-31

`spring:columns` reads or writes one property of many units in one host call. Values cross as
planes of 4-byte values: every unit's first component, then every unit's second, and so on, so
guest and host loop over plain arrays (and the guest can load four lanes at a time). It is not
a batch of arbitrary calls: one property per call.

Each entry runs the native read or write of the matching per-unit import, with that import's
visibility rules (`WasmUiVisibility` in unsynced and UI modules), so values, refusals and
synced results are the per-unit import's. What changes is the number of Wasm-to-host
transitions, import guards and wire encodings: one for the column instead of one per unit.

Source: `rts/WasmInterface/core/bindings/WasmCoreColumnsBindings.cpp`; SDK:
`spring.columns()` (`rust/crates/spring-sdk/src/columns.rs`, raw imports in
`spring-sdk-internal/src/columns.rs`). The native SDK backend runs the per-unit calls.

## Imports

| Import | Signature | Environments |
|---|---|---|
| `get-units(property, ids, count, args, arg, out, out-bytes, found)` | `i32 x8 -> i64` | all |
| `set-units(property, ids, count, args, arg, values, values-bytes, done)` | `i32 x8 -> i64` | synced |
| `get-units-rules-param(name, name-bytes, ids, count, out, found)` | `i32 x6 -> i64` | all |

- `ids`: `count` unit IDs (i32). `out`/`values`: `components x count` 4-byte values, planar.
  `out-bytes` smaller than that returns `BufferOverflow` with the size needed.
- `args`: an i32 per entry, or 0 to give every entry `arg` (an ally team, a weapon number).
- `found`/`done`: optional (0 for none), a byte per entry: 1 where the per-unit import would
  have succeeded. Refused entries read as 0.
- The result packs the count found (or applied) in the low word and a status in the high
  word, as the other Core imports.

## Properties

The numbers are ABI and never change.

| # | Property | Values per unit | Per-unit import |
|---:|---|---|---|
| 1 | position | f32 x3 | `get-unit-position` |
| 2 | mid position | f32 x3 | `get-unit-position` (`mid_pos`) |
| 3 | aim position | f32 x3 | `get-unit-position` (`aim_pos`) |
| 4 | velocity | f32 x3 | `get-unit-velocity` |
| 5 | vectors | f32 x9: front, up, right | `get-unit-vectors` |
| 6 | ally team | i32 | `get-unit-ally-team` |
| 7 | team | i32 | `get-unit-team` |
| 8 | def | i32 | `get-unit-def-id` |
| 9 | alive | i32 0/1, always found | `valid-unit-id` and not `get-unit-is-dead` |
| 10 | cloaked | i32 0/1 | `get-unit-is-cloaked` |
| 11 | health | f32 x2: health, max | `get-unit-health` |
| 12 | radius | f32 | `get-unit-radius` |
| 13 | in LOS (arg: ally team) | i32 0/1 | `is-unit-in-los` |
| 14 | in radar (arg: ally team) | i32 0/1 | `is-unit-in-radar` |
| 15 | stunned | i32 0/1 | `get-unit-is-stunned` |
| 16 | weapon target (arg: weapon from 1) | type i32, unit i32, x y z f32 | `get-unit-weapon-target` |
| 17 | fire state | i32 | `get-unit-states` |
| 18 | move state | i32 | `get-unit-states` |
| 20 | MoveCtrl velocity (set) | f32 x3 | `move-ctrl.set-velocity` |
| 21 | direction (set) | f32 x6: front, right | `set-unit-direction` |

`get-units-rules-param` reads a float unit rules parameter by name for every unit, as
`get-unit-rules-param-f32` does (absent or not a float: 0, not found).

Writes apply in the order of the IDs given; a guest that used to interleave two per-unit
writes per unit (direction, then velocity) and now writes two columns gets the same state
only when no write depends on another unit's earlier write, as for flights.

## Use and measurement

Ship Game (`rules-synced/src/host/columns.rs`, cfg `spring_columns`) reads its frame's bodies
(ally, place, velocity, kind), whether hulls are targetable, cloaked or seen by each alliance,
the velocities its navigator needs and the Lancer planning cache's alive/ally/targetable facts
as columns, and flies its station ships with two column writes. In its dense 2,000-ship
battle engine calls fell from about 90,700 to 64,400 a frame with identical state; see the
game's `docs/reports/2026-10-31-engine-main.md` for times. The calls left are mostly made from
unit scripts the engine invokes one unit at a time (turret tracking, hold-fire checks), where
no guest-side column applies.
