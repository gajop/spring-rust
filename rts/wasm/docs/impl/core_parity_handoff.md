## 1. Implemented seam

The probe body still targets the stable semantic path
`crate::bindings::recoil::spring_api::{module}::{function}`. The binding
generator swaps that path to `spring_wasm_core::owned` for Core guests, so the
probe cases, records, projections, and fixture inputs remain shared between
transports.

The owned façade is generated by
`rust/crates/spring-native-codegen/src/render_core_wasm_owned_guest.rs` and is
included by `rust/crates/spring-wasm-core/build.rs` as
`rts/wasm/generated/sdk/core_owned.rs`. It provides:

- owned forwarding for fixed and fixed-option Core callouts;
- borrowed-input adapters for strings and scalar lists;
- caller-owned flat list and string output retries;
- reviewed message, unit, projectile, terrain, and units-info adapters;
- semantic enum, record, option, and multi-output conversions;
- explicit typed `UnsupportedHostTarget` entries where the owned transport
  does not yet have a decoder or input adapter.

The Core guest supports context feature flags:

```text
core,core_rules_synced
core,core_rules_unsynced
core,core_gaia_synced
core,core_gaia_unsynced
core,core_ui
```

The harness writes dedicated Core artifacts such as
`recoil_wasm_parity_guest.synced_gadget.core.wasm` and
`wasm_api_probe_tests_synced_gadget_core.lua`; Component artifacts keep their
historical names. This prevents one transport build from overwriting the
other transport's checked-in probe source.

`WasmRuntimeConfig::maxImports` is 2048. A complete generated Core context can
legitimately declare several hundred imports, while the fixed bound still
limits untrusted module validation.

## 2. Core selection and accounting

The raw Core registry reports every technically executable import, but a parity
case must also be callable through the owned semantic façade. The Core probe
manifest therefore accounts for three distinct decisions:

1. production import/process/environment policy;
2. owned façade support;
3. ordinary probe eligibility (rendering, native-only, deferred, and similar
   fixture rules).

For the synced and Gaia-synced contexts the current Core manifest contains 307
selected cases from 507 canonical source rows. The remaining rows are visible
in `coverage.excluded`, including 186 `core_owned_unsupported` rows and seven
`core_policy` rows, with the ordinary deferred/rendering/output exclusions
accounted for separately. No unsupported façade entry is allowed to appear as
a passing Wasm observation.

The broader plan remains useful for transport inventory and future adapter
work. It scans only the canonical Component manifests; the separate
`.core.json` files are execution selections, not additional oracle cases. Its
current summary is:

```text
tests_total                          1288
tests_core_executable                 1288
tests_blocked                            0
tests_unmapped                           0
core_executable_callouts             1354
core_generated_callouts              1291
core_reviewed_handwritten_callouts     63
core_executable_callouts_with_oracle  681
core_executable_callouts_without_oracle 673
missing_callouts_blocking_oracle_tests  0
```

The difference between the plan's 1288 mapped cases and the 307-case runtime
oracle is intentional: the plan describes raw Core registry coverage across
contexts, while the oracle describes the currently generated owned semantic
surface in the contexts already run. The three remaining contexts must be run
and reported; they must not be represented by empty or skipped results.

## 4. Remaining work

The remaining `core_owned_unsupported` rows are not hidden transport failures;
they are explicit adapter work. The main groups are dynamic/recursive output
decoders, variable-input descriptors, command and piece record lists, rules and
configuration string/list APIs, and mutating control callouts. Extend the
generator from the shared Core field walk, reduce the manifest exclusions, and
rerun all five contexts.

The policy correction does not make mutating APIs valid in unsynced or UI
contexts. Those environments are runtime-enabled, but
`permitsSimulationMutation == false`; probes must either use read-only cases or
record the policy error as the expected native/Wasm result. Do not turn
missing observations into success.

Component Model removal is not part of this completed handoff. Keep the
Component path until the owned Core façade covers the intended API surface and
the runtime policy has an approved five-context plan.

## 5. Assumptions and review notes

- Core pointer values are valid only on `wasm32`; non-wasm façade calls return
  `UnsupportedHostTarget`.
- Caller-owned output capacities are retried only after the host reports the
  required count/byte length.
- Reviewed handwritten signatures in `WasmCoreRegistry.h` win over generated
  signatures; the generated registry verification checks for collisions.
- The fixed import bound of 2048 is a validation limit, not an ABI promise.
- Generated files under `rts/wasm/generated/` are never hand-edited.
